# 一括完了報告書PDF・対応日検索・作成中表示

## 利用方法

管理者の「完了報告書一覧」から、工事完了案件のチェックボックスを2〜8件選び「選択した完了報告書を一括PDF出力」を押します。選択した案件と完了報告書の種別が一括生成画面へ引き継がれます。全件のA4ページ・写真・署名を確認し、各報告書の「この報告書を確認しました」を押すと、1つのPDFとしてダウンロードできます。「個別PDFをZIPで保存」も選択できます。社員以上はサイドバー「報告書一括PDF／ZIP」から従来同様に生成できます。

案件一覧のステータス検索（失注を含む）と日付検索を組み合わせます。日付は初回対応実績、対応予定、現調実施、施工予定、依頼日から選択できます。日本時間の暦日で開始・終了を含む期間を比較し、開始のみ・終了のみも利用可能です。入力済み／未設定を選択でき、日付条件または全検索条件を解除できます。予定日や依頼日を未入力の実績に代入しません。

個別PDFのプレビューではフォント準備、写真取得、A4ページ描画の段階を「作成中…」として表示します。個別保存、一括生成、PDF結合、ZIP生成、個別履歴保存の間も待機状態を表示し、同じ操作の重複実行を防ぎます。

## 制約と安全性

| 項目 | 仕様 |
|---|---|
| 一括上限 | 2〜8件、入力合計80MB、個別履歴PDF30MB、結合PDF80MB・400ページ以内 |
| 内容の保全 | pdf-libで確認済み個別PDFの全ページを選択順にコピー。再描画・再圧縮をしない |
| 事前確認 | 全件プレビュー確認が終わるまで出力不可。生成後の保存前にも権限・案件状態をAPIで再確認 |
| 権限 | 一括生成は社員以上、完了報告書一覧は管理者以上。APIのエリア制限を維持。協力業者／顧客へ一括機能・履歴APIを公開しない |
| 対象 | ステータス完了または記録済み完了日のある案件。ただし失注は完了日が入っていても完了報告書の対象外。工事未完了の現調報告書を完了報告書として生成しない |
| 履歴 | 個別PDFを従来と同じUUID・SHA-256方式で保存。結合PDF自体の履歴登録は行わず、原本の個別履歴で再確認可能 |
| 障害時 | 欠損画像・破損PDF・ページ数不一致・容量超過は停止。写真を捏造せず、失敗したまま一部だけのPDFを出力しない |
| 表示負荷 | カード・県別表示は30件ずつページ送り。検索結果件数は全件の件数を維持し、検索条件変更で先頭ページへ戻る。表／コンパクトは既存の仮想スクロールを維持 |
| データ | DBスキーマ変更なし。実案件の予定・実績日・ステータスを一括更新しない。Resendは接続・実装しない |
