# プレナス現場チェックブック — 本格運用に向けた提案書

作成日: 2026年6月9日 / 対象: 本番運用フェーズへの移行と協力業者の取り込み

---

## 1. 結論（先に要点）

このアプリは社内の案件管理・見積・写真台帳・スケジュール・レポートまで一通り揃っており、**社内運用はすぐに始められる完成度**です。一方で「協力業者を巻き込む」には、現状の**公開共有リンク（PartnerView）だけでは一方通行**であり、業者側からの**見積提出・日程回答・写真アップロード・進捗報告を受け取る双方向の仕組み**が不足しています。

本格運用は次の3段階で進めるのが現実的です。

| フェーズ | 目的 | 期間目安 |
| --- | --- | --- |
| フェーズ1：社内本番化 | 権限・データ整備・公開・運用ルール確立 | 1〜2週間 |
| フェーズ2：協力業者の片方向連携 | 業者へ案件共有・通知を届ける | 2〜4週間 |
| フェーズ3：協力業者の双方向連携 | 業者から見積・日程・写真・報告を受け取る | 1〜2か月 |

---

## 2. 現状の棚卸し（実装済み機能）

データベースは `users / cases / checklistItems / photos / partners / estimates / routeAssignments / teamSettings / teamMembers / expenses` の10テーブルで構成され、主要機能は以下が実装済みです。

- 案件管理（一覧・地図・詳細・新規・PDF/CSV取込）、進捗ステージ⇔ステータス連動
- 見積取込（出し見積・実行指値の手入力／AI抽出）、粗利のリアルタイム表示
- 写真台帳（単一・複数案件の一括PDF、EXIF回転補正）
- 協力会社マスタ（カテゴリー・担当者・エリア・発注履歴）
- スケジュール盤（チームA/B、複数メンバー、担当者のチーム絞り込み）
- 経費管理、月次・担当者別レポート、ワークロード集計
- **協力業者向け公開ビュー（PartnerView）**：トークン付きリンクで、見積を75%金額のみ表示（原価は非開示）

> 補足：PartnerView は「閲覧専用・ログイン不要・トークンで案件1件を共有」という設計で、すでに**情報漏えい配慮（原価を返さない）**ができています。これは双方向連携の良い出発点です。

## 3. フェーズ1：社内本番運用の立ち上げ（最優先）

機能追加より先に、**運用に耐える状態を作る**ことが重要です。

### 3.1 公開とアクセス管理
- 独自ドメイン（`plenuscbk-l2kpa2gk.manus.space`）で公開済み。社内に周知。
- **管理者（admin）と一般（user）の役割を整理**。レポート・経費・チーム設定は admin 限定になっているため、誰を admin にするか決定する。
- 初回ログインしたメンバーを admin へ昇格する運用手順を文書化（現状はDB/設定で role を変更）。

### 3.2 マスタ整備
- 協力会社マスタ（partners）に**実際の取引業者を一括登録**（CSV取込あり）。カテゴリー・対応エリア・担当者連絡先を埋める。
- 「小林工房（元請け／三好慶）」のような特殊な立場の業者の扱いをルール化。

### 3.3 運用ルールの確定
- 進捗ステージの定義（未対応→現調済→見積提出済→承認済）と、誰がいつ更新するか。
- 写真の撮り方・命名・台帳化のルール（提出様式）。
- バックアップ方針（DBデータは復元不可のため、月次でCSV/レポートのエクスポート保管を推奨）。

### 3.4 追加で入れておくと安心な機能
- **操作ログ／変更履歴**（誰が案件・見積・ステータスを変えたか）。トラブル時の追跡に有効。
- **案件一覧の合計サマリーバー**（合計出し見積・実行・粗利）でフィルタ後の採算を即把握。

## 4. フェーズ2：協力業者への「片方向」連携（比較的すぐ実装可能）

まずは**業者にこちらから情報を届ける**部分を強化します。既存の PartnerView を活かせるため、開発コストは小さめです。

### 4.1 共有リンクの強化
- **有効期限・失効（revoke）ボタン**：現状トークンは無期限。期限切れ・手動失効を追加し、漏えいリスクを低減。
- **アクセスログ**：いつ業者が閲覧したか記録（開封確認）。
- **複数業者への出し分け**：1案件を複数業者に相見積もりで共有する場合、業者ごとに別トークンを発行して誰がどのリンクか識別。

### 4.2 通知（届ける手段）
- **メール／SMS送信**：共有リンクを業者の連絡先（partners.email / picPhone）へ自動送信。「新規依頼」「現調日確定」「見積依頼」などのテンプレート。
- **LINE連携**（任意）：建設・設備業界はLINE利用が多いため、LINE公式アカウント経由の通知も有効。

> 実装ポイント：メール送信はサーバー側から行います。本番ランタイム（Cloud Run）はNode単一プロセスのため、送信は外部メールAPI（SendGrid等）またはManus内蔵通知APIの活用が前提になります。

## 5. フェーズ3：協力業者からの「双方向」連携（本命・要設計）

ここが「協力業者を入れ込む」ための核心です。業者から**回答・提出を受け取る**には、現状不足している以下の機能が必要です。

### 5.1 協力業者アカウント／本人確認（最重要）
現状の PartnerView は**ログイン不要のトークン閲覧のみ**。業者が「書き込む」には、なりすまし防止のため最低限の本人確認が要ります。選択肢は2つ。

| 方式 | 内容 | 長所 | 短所 |
| --- | --- | --- | --- |
| A. 軽量（推奨スタート） | トークン＋ワンタイムコード（メール/SMS）で都度認証 | 業者の負担が小さい、アカウント管理不要 | セッション管理が簡易 |
| B. 本格 | 協力業者専用ログイン（partner role を追加） | 履歴・複数案件の一元管理、権限制御 | users テーブルへの role 拡張と業者招待フローが必要 |

→ **まずAで開始し、利用が定着したらBへ移行**するのが現実的です。Bにする場合、`users.role` に `partner` を追加し、業者を `partners` レコードに紐付ける設計（`partners.userId`）が必要です。

### 5.2 業者から受け取る機能（新規実装が必要）

1. **見積の提出（業者→自社）**
   - 業者が金額入力またはPDF/写真アップロードで見積を提出。
   - 自社側は「見積提出済」へ自動でステージ前進＋担当者へ通知。
   - 相見積もり時は複数業者の提出を**横並び比較**できるUI。

2. **日程の回答・調整**
   - 現調日・施工日の候補をこちらが提示し、業者が**可否を回答**。確定でスケジュール盤に反映。
   - カレンダー連携（業者側の空き提示）まで広げると調整が激減。

3. **施工写真・完了報告のアップロード（業者→写真台帳）**
   - 業者が現場写真を直接アップロード→自社の写真台帳に自動集約（EXIF補正は既存ロジック流用）。
   - 「着手前／施工中／完了」など区分タグ。

4. **進捗ステータスの業者更新**
   - 業者が「着工しました」「完了しました」を報告→自社のステータスに連動（承認は自社側）。

5. **メッセージ／やり取り（案件ごと）**
   - 電話・メールに散らばる連絡を案件単位のスレッドに集約。写真・ファイル添付対応。

### 5.3 受け取ったデータの審査・承認フロー
- 業者の提出（見積・写真・報告）は**いったん「申請中」**として受け、自社担当者が**承認して正式反映**する二段階を推奨。誤登録・不正を防げます。

## 7. 推奨ロードマップ（最短ルート）

1. **今すぐ**：社内本番化（権限整理・マスタ登録・運用ルール・サマリー/履歴）。
2. **次に（2の#1,#2）**：共有リンクの失効・期限＋業者へのメール/SMS通知。ここまでで「業者に確実に届く」状態。
3. **その後（3の#3,#4）**：OTP認証＋見積オンライン提出。ここで初めて「業者が書き込む」双方向が成立。
4. **拡張（3の#5〜#9）**：写真・日程・メッセージ・承認フロー、最終的に業者ポータル。

## 8. 技術・運用上の注意点

- **本番ランタイムの制約**：Node単一プロセス／リクエスト180秒／常駐ワーカー不可。メール送信・定期通知は外部API or 内蔵通知/定期実行（Heartbeat）で実装する必要があります。
- **データ復元不可**：DBは復元できないため、業者連携で書き込みが増える前に**定期エクスポート（バックアップ）運用**を必ず確立してください。
- **個人情報・原価情報の保護**：業者には原価・粗利を見せない設計を維持（PartnerViewは対応済み）。双方向化で項目が増えても同原則を徹底。
- **段階導入**：一部の協力業者でパイロット運用→フィードバック→全体展開、が安全です。

## 9. 次アクションのご提案

最初に着手するなら、効果が大きく実装も比較的軽い次の2つを推奨します。

- **(A) 共有リンクの失効・有効期限＋業者へのメール/SMS通知**（フェーズ2の#1・#2）
- **(B) 業者の見積オンライン提出（OTP認証付き）**（フェーズ3の#3・#4の入口）

どれから着手するかご指定いただければ、その機能の詳細設計とtodo化、実装に進みます。
