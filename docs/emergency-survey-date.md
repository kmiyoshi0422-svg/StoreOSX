# 緊急・漏電案件の現地対応日（現調実施日）

## 操作

1. 社員以上で対象案件の詳細を開き、**基本情報 → 緊急案件の現地対応日（現調実施日）**へ進む。
2. 実際に現地で調査した日を選ぶ。依頼日から自動入力しない。根拠の種類（完了報告書、現調報告書、担当者への確認、その他）と資料名・確認内容を必ず記載して保存する。日付の訂正・解除にも根拠または解除理由を入力する。
3. 「依頼日との比較」は日本時間の暦日が同一なら「当日現調（登録日付に基づく）」、異なれば「別日対応」と表示する。日付未登録は判定不可。
4. 現場調査報告書の「現調日」と、記録済みの場合のみ完了報告書の「現地対応日（現調）」に反映する。印刷・PDF前にプレビューで確認する。

## 範囲と非連動

- 対象は緊急度 **S** または依頼内容・工事分類に「漏電」が明記された案件。社員以上で当該案件のエリア権限を持つ人のみ更新・変更履歴を閲覧可能。協力業者・顧客は更新も履歴取得も不可。
- 入力先は既存の `cases.surveyDate`。実在する過去・当日の日付を1件ずつ入力する。将来日は不可。依頼日がなければ同日判定は不可。更新・訂正・解除は前後の日付、根拠、入力者、登録日時を `emergency_survey_date_logs` に記録する。
- **施工日・完了日・進捗ステージ・ステータスは自動変更しない。**「未対応」表示を変更する必要がある場合は、現調日とは別に実態を確認して案件の進捗を更新する。
- 従来の至急案件KPIは `surveyDate` がある案件を対象に、依頼日時から「当日/翌日」の既存基準で集計する。この画面の「当日現調」（暦日同一）とは別の指標。記録未確認の日付を入力しない。
- 完了報告書では単なる案件更新日時を完了日と見なさず、`completedAt` が未登録なら「—」と表示する。現調日の入力で完了日を作らない。
