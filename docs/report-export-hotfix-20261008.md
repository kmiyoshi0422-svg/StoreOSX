# 報告書PDF出力・テストデータ清掃（2026-10-08）

## 調査結果と修正

直近実案件301044-1（や）本厚木店）で、管理者の現調・完了報告書は修正前でもA4プレビューとPDF保存まで成功した。ユーザーが失敗した具体的な案件・画面・エラーは確認依頼中で、**すべての報告書障害の原因を特定したとは言えない**。

確認できた問題を修正した。未プレビューのPDF保存ボタンが無効で進めないように見えるため、報告書の「PDF出力」を押すとA4プレビューへ進み、確認後に保存できる導線に変更した。プレビュー未完了・本文変更・写真取得失敗時の保存停止は維持した。モバイルのプレビューヘッダー操作が重なる問題を折り返しで解消し、A4全体を画面幅に合わせ、画像・接続エラー時に再試行ボタンを設けた。

協力業者の報告書画面が社内専用の除外辞書・AI設定・保留タスクAPIを呼び403になる問題を抑止した。社外PDF出力後には社内専用の履歴APIを呼ばない。社内の生成履歴保存・署名・Before/After・案件権限は維持した。API権限は拡張していない。

## 実ブラウザ検証

既存の権限ある管理者・許可エリアの協力業者セッションで、現調3ページと完了5ページのプレビューを描画した。管理者・協力業者ともエラー0。390px幅で「PDF出力」→「PDFダウンロード」を実クリックし、A4ファイル保存と現調写真3枚の描画を確認した。実案件へテスト履歴を残さないよう、ブラウザ検証時だけ履歴アップロードをモックした。これはPDF生成・保存の実検証であり、今回の履歴API実保存試験ではない。

依頼番号・店舗名で明確なテスト案件を照会した結果、清掃前は0件。通常の実案件は588件。名称が「履歴テスト＋13桁時刻」「テスト電気／給排水＋13桁時刻＋A/B」で、実ユーザーや案件・業者通知への参照がないテスト業者89件をトランザクションで削除した。削除前の私的バックアップをプロジェクト外に保管した。清掃前後の実案件ID・依頼番号・ステータス・進捗・partnerIdのSHA-256が一致し、実案件状態を変更していない。

再発原因はcases.test.ts内の履歴テストで2件中1件だけ清掃していたことと、業者一括登録テストで生成業者を清掃していないこと。案件・業者をこのテストが生成した識別子だけで清掃する処理を追加した。
